# История изменений

## Не выпущено
- Тестовые механизмы аварийного завершения Lua worker исключены из подписанных APK. Смерть worker учитывается один раз независимо от порядка Binder callbacks.

- Оконный тайл открывается в Classic. В меню пустого пространства есть прямой вход в терминал.

- Developer Edition импортирует подписанные локальные пакеты и поддерживает отзыв доверия к публичным ключам. Локальное исполнение отключено.
- Отзыв допуска официальных Lua-тайлов сериализован с Binder dispatch и фиксацией состояния и UI.
- Внешний Lua ограничивает число активных и ожидающих операций worker. Зафиксированы результаты физической проверки SDK и Developer Edition.

- Добавлена отдельная конфигурация Developer Edition для проверки UID, данных и состава APK. Допуск пользовательских Lua-пакетов закрыт. [Граница выпуска](docs/DEVELOPER_EDITION.md).
### Установка и проверка HOME

- Основной HyprDroid доступен как домашнее приложение и открывается по иконке. CI проверяет выбор HOME после обновления APK с постоянной подписью.
- Ручная подписанная сборка основной версии может явно включить тест опубликованного Hello Tile. Обычные сборки оставляют внешний Lua выключенным.

### Plugin API v2

- Clock Tile и Battery Tile 1.0.0 доступны из подписанного публичного каталога ревизии 2. Состояние тестовых тайлов переносится только явно после проверки точного архива.

- Core проверяет актуальность даже неизменённых снимков v2 перед публикацией UI. Добавлена проверка состояния Clock через завершение процесса и повторный запуск.

- Добавлены валидаторы манифеста, декларативного UI и скалярного состояния, а также правила маршрутизации событий и таймеров v2. Тестовый APK с отдельным флагом запускает локально подписанные Clock Tile и Battery Tile в существующем изолированном worker. Обычная политика допуска сохранена.

### Инфраструктура внешних пакетов

- Изолированный Lua worker игнорирует чужие и повторные Binder-запросы. Core отменяет активный вызов при отзыве пакета и ограничивает повторные запуски после серии аварий.

- Hello Tile восстанавливает свой счётчик из хранилища Core после пересоздания UI и перезапуска приложения.

- HyprDroid Experimental устанавливается рядом с основным приложением и хранит отдельные настройки и пакеты.

- Добавлены проверяемый каталог GitHub Releases, защищённый от отката кэш и короткие имена пакетов. Ключ издателя закреплён с минимальной ревизией 1. Подписанный каталог первой ревизии содержит Hello Tile 1.0.0.
- Подписанные сетевые пакеты используют существующий установщик. Экспериментальный worker Lua 5.4 допускает точную опубликованную версию Hello Tile после повторной проверки установки. Сборка по умолчанию отключает внешний Lua. [Проверка и ограничения](docs/SAFE_EXTERNAL_LUA_TESTING.md)

### Inline prompt терминала

- Prompt снова идёт сразу за последним выводом внутри журнала. Подсказки и навигация по истории прокручиваются вместе с ним.
- У ввода и вывода общий Canvas. При ручной прокрутке каретка учитывает положение строки, а новое редактирование возвращает активную строку в видимую область.

### Tile Plugin API v1

- Встроенный Lua DroidFetch рисует декларативный интерфейс в существующем тайле и обновляет реальные системные данные через Refresh.
- Добавлены проверка установки подписанного образца, команды `hypr tile` и ограничения на дерево, события и состояние. [Контракт](docs/TILE_PLUGIN_API.md)

### Terminal QoL

- Вставка LF и CRLF готовит очередь с предпросмотром. Команды выполняются по очереди после подтверждения, ошибка останавливает пакет, а отмена пропускает ещё не начатые команды.
- История последних 100 команд сохраняется между запусками. Добавлены навигация, `history`, `history clear` и подсказки команд и пакетов.
- Поле ввода закреплено отдельно от журнала. Ошибки выделены цветом, ручная прокрутка приостанавливает слежение за выводом, кнопка «К концу» возобновляет его.

### Lua Plugin Runtime v0.1

- Команда `lua run droidfetch` запускает встроенный скрипт в изолированном Android-сервисе. Plugin API v1 передаёт сведения об устройстве и батарее и выводит текст в терминал и диалог HyprDroid.
- Добавлены проверки разрешений и лимиты исполнения. Доступ на запуск пока ограничен скриптами из APK. [Архитектура и ограничения](docs/LUA_RUNTIME.md)

### Hypr Package Manager v0.1

- Терминал получил команды `hypr help/search/list/info/install/remove/update`. Локальный тестовый каталог содержит реально устанавливаемый `.hyp`.
- Добавлены проверки SHA-256 и Ed25519, валидация манифеста, лимиты распаковки, установка зависимостей и атомарная публикация реестра. [Формат и ограничения](docs/PACKAGE_MANAGER.md)

### Плавное движение курсора терминала

- Каретка ввода следует за реальным выделением и горизонтальной прокруткой поля. Каретка вывода следует за строками и границей заполненной части шкалы `demo install`.
- Пружина сохраняет скорость при смене цели. Курсор слегка растягивается при быстром движении, а шлейф затухает вдоль пройденных позиций.
- Координаты ограничены областью журнала. При прокрутке курсор и шлейф смещаются вместе с содержимым.

### Dynamic Terminal Cursor — потоковый вывод команд

- `CommandProcessor` получил безопасный потоковый результат `CommandResult.Stream` с событиями `Line`/`Progress`/`Pause`. Процессор по-прежнему не запускает процессы, не спит и не обращается к файловой системе: задержки проигрывает UI.
- Новая команда `demo install` — детерминированная имитация установки модуля: подготовка, зависимости, загрузка, контрольная сумма, распаковка и регистрация. 42 события, прогресс обновляется на одной строке, общая длительность ~2.7 с. `demo` без аргумента показывает подсказку, `help` дополнен командой.
- `CommandPanelState` проигрывает поток с отменой предыдущего запуска, ограничением 200 строк и заменой последней строки для `Progress`; `help`, `clear`, `modules`, `date` и `droidfetch` не изменились.
- `AnimatedTerminalCursor` переведён на 2D-анимацию по реальным координатам каретки: плавное движение по строкам, шлейф со свечением и растяжением по вертикали/диагонали, затухание и мигающий блок. Геометрия вынесена в чистую функцию `cursorTrail` и покрыта unit-тестами.
- Во время стрима анимированный курсор следует за последней строкой вывода, а нативная каретка скрыта; в покое возвращается обычная каретка ввода, поэтому редактирование середины строки не ломается.
- Раскладка терминала (LazyColumn + строка ввода), Catppuccin Mocha и существующие команды сохранены.
- Локально: `:app:testDebugUnitTest` — 167 тестов, 0 fail; `:app:assembleDebug` — успешно.

### Stage 7.1 — изменение размеров тайлов в реальном времени

- Двухпальцевый вертикальный и диагональный жест обновляет геометрию тайлов во время движения пальцев, а не после отпускания: `TilingSurface` показывает временный snapshot движка и пересчитывает `calculateLayout()` на каждом pointer event.
- В начале жеста один раз выбираются разделители для вертикальной и горизонтальной осей, запоминаются их исходные ratios и независимый snapshot `WorkspaceEngine`. Основной движок во время preview не мутируется, промежуточные ratios не пишутся в DataStore.
- Итоговые ratios вычисляются от исходного положения пальцев и исходного ratio (`baseRatio + delta / extent`), поэтому быстрые движения, смена направления и повторные события не накапливают ошибку. Диапазон ограничен минимальными размерами обоих поддеревьев через `WorkspaceEngine.splitRatioBounds`.
- При завершении сохраняются только фактически изменённые ratios; preview удерживается до прихода опубликованного состояния, затем сбрасывается, поэтому нет скачка к старой геометрии. Отмена жеста, исчезновение второго пальца, смена workspace и dispose поверхности отбрасывают preview без записи.
- `pointerInput` не пересоздаётся на кадрах preview; горизонтальное разведение/сведение, `+`/`×`, ModuleHost, независимые workspace и восстановление после перезапуска сохранены. Визуальные разделители не возвращались.
- Unit-тесты: выбор разделителей обеих осей, абсолютный расчёт ratios, быстрое движение и смена направления, минимальные размеры, изоляция preview/отмена, последовательные resize и диагональ. Локально: 145 тестов, 0 fail.

### Исправление — независимый тайлинг рабочих пространств

- `WorkspaceUiState.tiling` хранит карту сессий по `workspaceId` вместо единственного `TilingState`. Открытие или изменение тайлов в одном пространстве больше не заменяет и не скрывает тайлы другого.
- `WorkspaceEngine` по-прежнему отдельный для каждого workspace; деревья split, `SplitId`/ratios, `moduleId`, фокус и размеры сохраняются при переключении страниц.
- Закрытие поверхности и удаление последнего тайла затрагивают только своё пространство; остальные сессии остаются открытыми.
- Флаг `tiling/<workspaceId>/open` теперь записывается при открытии/закрытии, поэтому после перезапуска восстанавливаются все открытые пространства, а не только последнее. Флаг закрытого пространства не удаляет его сохранённое дерево.
- Unit-тесты: тайлы в двух пространствах, переключение и публикация без затрагивания соседа, закрытие одного пространства, восстановление всех открытых пространств с деревом/модулем/фокусом и пропуск повреждённых ключей. Локально: 138 тестов, 0 fail; `:app:assembleDebug` и `:app:assembleDebugAndroidTest` — успешно.

### Stage 6 — внутренние модули тайлов

- Встроенная архитектура `TileModule`/`ModuleRegistry`/`ModuleHost`/`ModuleState`: у каждого тайла собственный экземпляр состояния, привязанный к `WindowId`; при смене модуля и закрытии тайла вызывается `dispose()`. Динамической загрузки стороннего кода нет.
- System Monitor раз в 2 секунды показывает ОЗУ, батарею/зарядку, хранилище, версию Android, устройство, ядра и аптайм публичными API. Недоступные без root нагрузка ЦП и температура обозначены в интерфейсе.
- App Launcher использует существующий каталог HyprDroid: поиск по названию/компоненту, иконки, запуск и адаптивная сетка для маленьких тайлов.
- Clock показывает время/дату. Command Panel — безопасная внутренняя консоль HyprDroid с командами `help`, `clear`, `modules`, `date`; произвольные shell/root-команды не выполняются.
- Module Picker выбирает модуль одним нажатием, меню заголовка меняет модуль существующего тайла. Новый тайл и неизвестный сохранённый id показывают нейтральный выбор.
- `WorkspaceEngine.setWindowModule` обновляет только `moduleId`, не меняя дерево, ratios и геометрию; выбранный модуль сохраняется прежней сериализацией движка и восстанавливается после перезапуска.
- Жесты создания/закрытия/resize, кнопки `+`/`×`, pager и сохранение раскладки не изменены.
- Unit-тесты покрывают реестр, независимость экземпляров, выбор/смену, сохранение, закрытие одного из нескольких и неизвестный `moduleId`. Локально: 133 теста, 0 fail; debug APK собирается. CI-проверка ожидается.

### Stage 5 — адаптивный внутренний тайлинг

- `WorkspaceEngine.addWindowAdaptive`: ориентация split выбирается по rect выбранного leaf (выше/шире — верх/низ, иначе лево/право), затем дерево перебалансируется под количество окон и portrait/landscape.
- Portrait: 2 окна — верх/низ, 3 — одно сверху и два снизу, 4 — 2×2; landscape — зеркально. 5–6 окон — сетка без нулевых размеров.
- Reflow переиспользует существующие `SplitNode`, `SplitId` и ratios, сохраняет окна и фокус; layout не даёт overlap и выхода за workspace, `canAddWindow` требует хотя бы 1 px на ячейку.
- Unit-тесты 2–6 окон (bounds, ориентации, поворот) и Compose UI-тест реальных bounds; жесты, pager, sidebar, дизайн и drag-разделители не изменены.
- Исправлена генерация WindowId после удаления тайла: создание новых окон и split в `WorkspaceViewModel.addTilingWindow` переведено на UUID, что исключает повторное появление удалённых идентификаторов и коллизии (регрессионные тесты: add 3 -> remove first -> add again).

### Workspace Engine v0.9 — архитектурный фундамент

- Внутренний пакет `dev.hyprdroid.launcher.workspaceengine`: чистый Kotlin-движок размещения без Android/Compose и новых зависимостей; модель `WorkspaceTree`, `SplitNode` (ratio 0.05..0.95), `LeafNode`, `WorkspaceWindow`, layout-геометрия.
- Отдельный DataStore `workspace_engine` со схемой движка; прежние workspace/shell/панелей хранилища и форматы не изменены.
- Операции движка (`addFirstWindow`, `splitWindow`, `removeWindow`, `focusWindow`, `resizeSplit`, `calculateLayout`) с явными результатами и типизированными ошибками без повреждения состояния; layout — чистая функция на px с нормализованным ratio и информацией о нарушении минимумов.
- Сериализация движка v1 с версионированием и валидацией; неизвестная версия схемы и повреждённое дерево — `IOException`. Начальное состояние — пустые деревья, миграция legacy не выполняется.
- Контракт `ModuleManifest` для будущих internal `.hmod`: id, name, version, entrypoint, permissions; без WebView, ZIP, JavaScript и исполнения.
- Unit-тесты: 13 тестов движка, контракт модуля, round-trip сериализации и DataStore; `:app:testDebugUnitTest :app:assembleDebug` — зелёные (81 тест, 0 fail).

### Производительность

- Запись настроек больше не разбирает и не сериализует JSON на главном потоке: трансформации DataStore выполняются в `Dispatchers.Default`. Порядок записей, валидация схем и исключения (`IOException`, `DockFullException`) не изменились.
- Редактор dock кэширует карту приложений и не пересобирает её на каждый символ поиска.
- Служба боковых панелей переиспользует уже показанное окно, если открытая сторона, настройки панелей и геометрия экрана (ширина, высота, плотность) совпадают, а активные ручки соответствуют ровно тем сторонам, которым нужен режим «Поверх приложений»; при смене конфигурации, геометрии или отвязке окна от WindowManager окно создаётся заново. Видимость и условия показа не изменились.
- Каталог приложений: декодированные иконки переиспользуются по компоненту, плотности и размеру, пока не изменился `lastUpdateTime` пакета; у ярлыков учитываются и `lastChangedTimestamp`, и время обновления пакета. Явное «Обновить приложения» перекодирует иконки принудительно. Кэш только в памяти, не более 32 МиБ, без `Bitmap.recycle()`.
- Возврат на Home больше не перезагружает каталог: обновление идёт по событиям `LauncherApps`, страховочной проверке раз в 15 минут по монотонному времени и явному пункту меню. События, пришедшие во время загрузки, не теряются. При фоновом обновлении индикатор загрузки не показывается, холодный старт сохранён прежним.

## 0.1.0 — начальный прототип

Обозначение версии в исходниках; отдельный опубликованный релиз не подтверждён.
