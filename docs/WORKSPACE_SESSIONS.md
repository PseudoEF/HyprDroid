# Workspace Sessions v0.7.3 (эксперимент)

Сессия — сохранённое назначение до двух запускаемых приложений текущего профиля каждому workspace. Это не набор управляемых окон и не снимок состояния процессов. Назначения независимы от иконок Classic, dock и панелей. Сессии по умолчанию отключены; выключение сохраняет назначения.

## Использование

Откройте меню верхней панели → **Workspace Sessions**, включите эксперимент, выберите номер workspace и добавьте приложения. Изменения сохраняются сразу. «Убрать» удаляет только назначение. Удалённое/отключённое приложение остаётся недоступным назначением: его можно убрать или восстановить переустановкой. Переключение workspace не закрывает, не замораживает и автоматически не запускает чужие приложения.

«Открыть / вернуться» отправляет стандартный MAIN/LAUNCHER Intent с `NEW_TASK | RESET_TASK_IF_NEEDED`. Android может вывести существующую задачу вперёд; поведение также зависит от launchMode, taskAffinity и реализации приложения. Не используются MULTIPLE_TASK, CLEAR_TASK, CLEAR_TOP или принудительное завершение. Даже стандартный запуск не гарантирует сохранение экрана приложения: жизненным циклом, вытеснением из памяти и восстановлением управляют Android и поставщик приложения.

«Попробовать Split Screen» отправляет одну последовательность `startActivities`: первый launcher Intent, второй с дополнительным `LAUNCH_ADJACENT`. Это best-effort запрос, а не подтверждение пары. Возможны полноэкранный запуск второго приложения, последовательное открытие, отказ или разделение с другим окном. Повторный запуск пары не гарантирует возврат прежнего расположения. Автоматический запуск из фонового сервиса, таймеры и обход ограничений запуска не используются.

Если пара не появилась: откройте первое приложение → системные **Недавние** → значок приложения → **Разделить экран** → выберите второе. Пункты зависят от Android/OEM, а некоторые приложения не поддерживают этот режим. HyprDroid не открывает Recents скрытым Intent и не выдаёт собственный экран за SystemUI. Обычный HOME и выбор другого лаунчера сохранены.

## Исследование публичных API Android 15–17

Проверено по официальной документации перед реализацией:

- [Multi-window](https://developer.android.com/develop/ui/views/layout/support-multi-window-mode): LAUNCH_ADJACENT вместе с NEW_TASK запрашивает соседнее окно. С Android 12L запрос может инициировать split из полноэкранного приложения, но результат зависит от устройства и текущих окон. Это не публичный API для произвольного составления пары чужих task ID из HOME. На небольшом экране ограничения resizability/minWidth/minHeight целевых приложений существенны.
- [Intent](https://developer.android.com/reference/android/content/Intent#FLAG_ACTIVITY_LAUNCH_ADJACENT): adjacent — запрос «если возможно»; MULTIPLE_TASK создаёт новые экземпляры и здесь не применяется. [Задачи и back stack](https://developer.android.com/guide/components/activities/tasks-and-back-stack) объясняют повторное использование NEW_TASK и ограничения гарантий состояния.
- [ActivityManager](https://developer.android.com/reference/android/app/ActivityManager#getRunningTasks(int)): сторонние приложения не получают общий список чужих задач через getRunningTasks; getAppTasks относится к собственным задачам. HOME-роль не делает приложение системным Recents/Quickstep. Код не перечисляет чужие задачи и не вызывает moveTaskToFront.
- [Android 15: безопасность запусков](https://developer.android.com/about/versions/15/behavior-changes-15#safer-intents) и [ограничения фоновых запусков](https://developer.android.com/guide/components/activities/background-starts): запуск из видимого Activity по явному нажатию предпочтителен; нельзя гарантировать вторичный фоновый запуск. Сессии не запускаются автоматически при смене workspace.
- [Android 16: адаптивность](https://developer.android.com/about/versions/16/behavior-changes-16#adaptive-layouts): изменения ограничений размеров на больших экранах не дают обычному лаунчеру привилегированного управления чужими окнами и не гарантируют split на Pixel 9.
- [Android 17: изменения](https://developer.android.com/about/versions/17/summary) и [release notes](https://developer.android.com/about/versions/17/release-notes): новые системные оконные возможности не означают доступ стороннего HOME к универсальному управлению задачами. Реальная совместимость конкретной сборки Android 17 требует проверки; API 36/37 здесь не вызываются, compile/targetSdk остаются 35.

Диагностика показывает Android/API, текущее multi-window состояние **собственного** Activity и low-RAM признак. Наличие константы LAUNCH_ADJACENT не представляется доказательством поддержки split. Определить реальное размещение чужих задач или факт их повторного использования надёжно нельзя.

## Данные и приватность

Два дополнительных ключа в существующем workspaces DataStore: JSON конфигурации v1 и журнал до 50 записей. Старые закрепления, схема workspace v2, shell, виджеты и обои не переписываются. Неизвестная версия/повреждённая конфигурация выдаёт ошибку и не заменяется пустой записью при обычном сохранении.

Журнал хранится только локально: время, номер workspace, тип действия, принятие запроса/ошибка. Успешный возврат `startActivity` отмечается **«отправлен, результат не подтверждён»**, а не «пара запущена». Нет названий окон, снимков, текстов, URI контента, списка чужих процессов или сетевой отправки. Журнал можно очистить отдельно от назначений.

## Проверка на физическом Pixel 9

Пока не подтверждено на телефоне:

1. Обновление подписанным APK поверх v0.7.2 через Android или `adb install -r`: прежние workspace, панели, widget ID, GIF и настройки остаются; About показывает новую сборку.
2. Назначения Termux + ChatGPT, Files + GitHub, Telegram + браузер сохраняются после завершения процесса/перезагрузки; выключение эксперимента не удаляет их.
3. Обычный запуск возвращается к существующему документу/терминалу, насколько это поддерживает само приложение. Сравнить холодный/тёплый запуск и состояние после нехватки памяти; не считать новый экран ошибкой восстановления HyprDroid без проверки поведения приложения.
4. Запрос пары из HOME на установленных Android 15/16/17: записать фактические окна, журнальный результат и наличие лишних задач. Не считать отправленный Intent доказательством split. Проверить ручной путь Recents и неподдерживающее split приложение.
5. Back, HOME, смена workspace, Clean/Classic, drawer, панели, виджеты и пауза GIF продолжают работать. Удаление/отключение приложения не приводит к падению; назначение можно убрать.

Сборка и тесты эмулятора не заменяют эти проверки.
