# Lua Plugin Runtime v0.1

В тайле «Команды» команда `lua run droidfetch` запускает встроенный `droidfetch.lua`. Скрипт печатает модель, версию Android и состояние батареи и показывает те же сведения в закрываемом диалоге HyprDroid. `lua help` показывает допустимый вызов.

## Выбор движка

Размеры относятся к опубликованным архивам и не равны изменению размера APK после сборки.

| Движок | Размер и Android ARM64 | Лицензия и контроль исполнения |
|---|---|---|
| LuaJ 3.0.1 | JAR 354 104 байта. Интерпретатор JVM без JNI. Отдельный ARM64-артефакт не нужен. | MIT. Можно создать пустой `Globals` и подключить закрытый счётчик инструкций через `DebugLib`. Аллокатор VM управляется JVM, поэтому отдельного надёжного лимита Lua-кучи нет. [LuaJ](https://github.com/luaj/luaj), [DebugLib](https://luaj.org/luaj/3.0/api/org/luaj/vm2/lib/DebugLib.html), [артефакт](https://repo.maven.apache.org/maven2/org/luaj/luaj-jse/3.0.1/luaj-jse-3.0.1.jar) |
| PUC Lua 5.4.8 через собственный JNI | Архив исходников 374 332 байта. Android NDK поддерживает `arm64-v8a`. Размер собственного `.so` зависит от параметров сборки и не измерялся. | MIT. `lua_newstate` принимает управляемый аллокатор, `lua_sethook` даёт счётчик инструкций. Понадобится небольшой JNI-слой, отдельная сборка для каждого ABI и проверка обработчиков ошибок C. [Исходники](https://www.lua.org/ftp/lua-5.4.8.tar.gz), [лицензия](https://www.lua.org/license.html), [Lua C API](https://www.lua.org/manual/5.4/manual.html), [Android ABI](https://developer.android.com/ndk/guides/abis) |
| LuaJava 4.1.0 с Lua 5.4 | JAR ARM64 180 550 байт, базовые Java-артефакты ещё 86 959 байт. Другие ABI добавляют собственные артефакты. | MIT для библиотеки. JNI использует нативный Lua, но LuaJava предоставляет мост к Java. Изоляция потребовала бы проверенного способа исключить мост и контролировать аллокации и инструкции. [LuaJava](https://github.com/gudzpoz/luajava), [Android ABI в документации](https://github.com/gudzpoz/luajava/blob/main/docs/getting-started.md), [артефакты](https://repo.maven.apache.org/maven2/party/iroiro/luajava/) |

Для прототипа выбран LuaJ. Он добавляет небольшой ABI-независимый интерпретатор и даёт JVM-тесты для Plugin API. Версия 3.0.1 выпущена в 2015 году, поэтому её возможности и долгосрочное сопровождение требуют отдельной оценки перед расширением доверия. Для запуска сторонних модулей остаётся открытым выбор движка с контролируемым аллокатором. MIT-уведомление LuaJ включено в APK.

## Граница доверия и IPC

1. Host распознаёт только идентификаторы из `BuiltInLuaPlugin`. Каждый идентификатор связан с конкретным asset и перечнем разрешений, заданным кодом. Runtime не читает приватный реестр Package Manager, произвольные пути или содержимое командной строки как код.
2. Host запускает неэкспортируемый `LuaPluginService` с `android:isolatedProcess="true"` через `bindIsolatedService` с уникальным именем. Android выделяет отдельный процесс без разрешений приложения. Для одного запуска создаётся одна привязка, параллельные запуски сериализуются. [Android service](https://developer.android.com/guide/topics/manifest/service-element#isolated), [Context.bindIsolatedService](https://developer.android.com/reference/android/content/Context#bindIsolatedService(android.content.Intent,int,java.lang.String,java.util.concurrent.Executor,android.content.ServiceConnection)).
3. `Messenger` передаёт версию протокола, ID и ограниченный снимок разрешённых полей. Сервис проверяет UID отправителя и заново находит ID в allowlist. Скрипт читает только DTO с данными устройства и батареи. Ответ передаётся приватному ответному `Messenger`, который проверяет отличный от host UID, размер и разрешения на эффекты. Host снимает привязку при ответе, таймауте, отмене или разрыве соединения. [Android Messenger](https://developer.android.com/reference/android/os/Messenger).
4. На один запуск создаётся пустое окружение Lua. В него добавлены компилятор текста, внутренний счётчик и таблица `hypr`. Скрипт не получает стандартные библиотеки, Android Context, Java-объекты, reflection, shell, файлы, сеть или загрузку байткода. При ошибке буфер эффектов отбрасывается целиком.

## Plugin API v1

| Вызов | Разрешение | Действие |
|---|---|---|
| `hypr.terminal.print(text)` | `terminal.print` | Добавить текст в вывод терминала. Принимает одну строку, которая может содержать переносы. |
| `hypr.system.getDeviceInfo()` | `system.device` | Получить `manufacturer`, `model`, `release` и `sdk`. |
| `hypr.system.getBattery()` | `system.battery` | Получить `percent` и `charging`. Недоступное поле имеет значение `nil`. |
| `hypr.ui.createWindow(title)` | `ui.window` | Создать описатель диалога внутри Home и вернуть целочисленный дескриптор. |
| `hypr.ui.showText(handle, text)` | `ui.window` | Заменить текст активного диалога. |
| `hypr.ui.closeWindow(handle)` | `ui.window` | Закрыть описатель. После закрытия дескриптор недействителен. |

Выполнение одноразовое. Встроенный модуль может подготовить один открытый диалог за раз. Итоговое состояние и вывод показываются только после успешного завершения, поэтому окно, которое скрипт успел закрыть, не появится. У окна нет системного overlay, обработчиков Lua после возврата и доступа к чужим тайлам.

## Лимиты и остаточные риски

- Размер UTF-8-исходника до 16 КиБ, до 50 000 инструкций, счётчик глубины 48 и проверка лимита 250 мс в ходе интерпретации. Host ожидает один ответ не дольше 5 секунд после начала привязки.
- До 64 вызовов Plugin API, 32 записей терминального вывода и 8192 кодовых единиц UTF-16 суммарного текста. Лимиты аргументов проверяются также до декодирования Lua-строки. За одно выполнение открыто не больше одного окна.
- Счётчик инструкций и проверка времени не дают строгого лимита аллокаций внутри инструкции либо времени разбора текста. Исчерпание памяти в worker может создать системное давление, даже с отдельным UID. Остановка привязки — ограничение ожидания host, а не доказательство немедленного завершения процесса.
- Изоляция зависит от целостности LuaJ, ART, Android и Binder-границы. Само отсутствие библиотек не делает загрузку недоверенного кода допустимой. APK запускает только встроенный образец, включая случаи, когда скачанный пакет имеет корректную подпись.

## Перед подключением к Package Manager

Требуется согласовать контракт, который передаёт worker только неизменяемую, проверенную точку входа и API-версию. Host должен проверить доверие к издателю, полученную подпись, установленную версию и разрешения пользователя для этого модуля. Манифест задаёт запрос, а каждое действие повторно проверяется по действующим разрешениям сессии. Отзыв доступа должен завершать запуск и закрывать связанные окна. Перед расширением протокола потребуются жёсткие квоты памяти, типизированный Binder-контракт вместо Bundle и проверка lifecycle, аварий и таймаутов на устройствах. Реестр и интерфейсы v0.1 остаются независимыми от рантайма. [Package Manager](PACKAGE_MANAGER.md)
