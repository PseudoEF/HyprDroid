# Hypr Package Manager v0.1

Команды доступны в тайле «Команды». Установка хранит проверенные файлы в приватном каталоге приложения и регистрирует пакет. Payload пакетов не исполняется. Подписанный образец DroidFetch разрешает встроенный Lua-тайл после проверки установки. [Tile Plugin API](TILE_PLUGIN_API.md) `demo install` по-прежнему проигрывает демонстрационный сценарий.

```text
hypr help
hypr search droidfetch
hypr list
hypr info hyprdroid.droidfetch-sample
hypr install hyprdroid.droidfetch-sample
hypr list --installed
hypr update
hypr remove hyprdroid.droidfetch-sample
```

## Каталог и доверие

В APK находится локальный тестовый каталог схемы 1 с одним архивом. Адрес официального сервера и ключи издателя пока не настроены. Приложение получает каталог из собственных подписанных ресурсов APK, а путь к архиву строит из валидированных ID и версии. Ресурсы можно обновить новой версией APK. Тестовый ключ не используется для других источников, его закрытая часть не сохранялась.

Запись каталога содержит копию манифеста, SHA-256 архива в hex, ID ключа и 64-байтовую подпись Ed25519 в hex. Проверяется подпись точных байтов всего архива доверенным публичным ключом, закреплённым в приложении. SHA-256 проверяется отдельно. Подмена каталога, доверенного ключа или источника из терминала не предусмотрена. Ed25519 проверяется через lightweight API Bouncy Castle с поддержкой minSdk 29. Платформенный `Signature("Ed25519")` доступен начиная с API 33. [Android Signature](https://android.googlesource.com/platform/prebuilts/fullsdk/sources/%2B/refs/heads/androidx-constraintlayout-release/android-35/java/security/Signature.java), [Bouncy Castle](https://www.bouncycastle.org/documentation/documentation-java/).

## Формат пакета

`.hyp` — ZIP с корневым `manifest.json` в UTF-8 и обычным файлом по пути `entry`. Пример манифеста:

```json
{
  "id": "hyprdroid.droidfetch-sample",
  "version": "1.0.0",
  "apiVersion": 1,
  "runtime": "lua",
  "entry": "droidfetch.lua",
  "permissions": ["terminal.print", "system.device", "system.battery"],
  "dependencies": {}
}
```

Поддерживаются числовые версии `major.minor.patch` без ведущих нулей, суффиксов и диапазонов. `dependencies` сопоставляет ID с минимальной версией. Менеджер добавляет доступные зависимости в одну операцию, отклоняет циклы и блокирует удаление пакета с зависимыми модулями. Манифест из архива должен совпасть с записью доверенного каталога по всем полям. `permissions` описывает запросы пакета и ничего ему не выдаёт.

До распаковки проверяется сжатый размер, до записи каждой записи — имя, объём и коэффициент сжатия. Допустимы до 8 МиБ на архив, 24 МиБ после распаковки, 8 МиБ на файл, 16 КиБ на манифест и 256 ZIP-записей. Ограничены глубина путей, длина имён, число пакетов и зависимостей. Запрещены абсолютные пути, `..`, обратные слеши, дубликаты имён и конфликты файлов и каталогов. Распаковщик создаёт только обычные файлы и каталоги, проверяет фактический размер и CRC каждой записи.

## Публикация и восстановление

`HyprPackageManager` не зависит от Compose и Android. `PackageCatalog`, `PackageArtifactSource` и `PackageRegistry` позволяют тестировать операцию без Activity и сети. Терминал вызывает менеджер на `Dispatchers.IO` через поток событий. Все терминалы приложения используют один экземпляр менеджера и сериализуют операции записи.

Проверенные пакеты готовятся в новых директориях. Результат установки или обновления всех зависимых пакетов публикуется единым атомарным переименованием файла `registry.json` в `noBackupFilesDir/hypr-packages`. При ошибке до публикации прежний индекс и его файлы сохраняются. Если процесс закрыт до публикации, подготовленные директории не видны через реестр. Следующая операция установки, удаления или обновления пытается их убрать. При ошибке очистки лишние директории могут остаться на диске. Изменение, для которого уже начался файловый ввод-вывод, может завершиться после закрытия терминала.

## За пределами v0.1

- Сетевой каталог, подпись его метаданных, защита от отката каталога и ротация ключей.
- Выбор между несколькими версиями, prerelease, долговременное хранение старых версий и ручной даунгрейд.
- Исполнение кода из реестра, выдача разрешений и интеграция скачиваемых пакетов с Module Picker.
- Проверка физической установки APK и поведения хранилища при внезапной потере питания.
