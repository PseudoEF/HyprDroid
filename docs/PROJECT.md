# Техническое описание HyprDroid

## Назначение

HyprDroid — экспериментальный Android HOME-лаунчер с рабочими пространствами и раскладками собственных элементов интерфейса, вдохновлённый Hyprland. Пользовательская инструкция находится в [README](../README.md), состояние задач — в [ROADMAP](ROADMAP.md).

Минимальная версия Android — 10 (API 29), `compileSdk` и `targetSdk` — 35. Базовые функции не требуют root, Shizuku, ADB, разблокировки загрузчика, AccessibilityService или привилегированных разрешений.

## Текущая реализация и архитектура

Приложение состоит из одного модуля `app` на Kotlin и Jetpack Compose с Material 3.

- `MainActivity` создаёт Compose UI и ViewModel. Регистрация `MAIN` / `HOME` / `DEFAULT` сохраняется.
- `model/WorkspaceSettings.kt` содержит модели трёх пространств со стабильными числовыми идентификаторами и независимыми наборами компонент приложений.
- `data/WorkspaceRepository.kt` хранит закрепления, текущее пространство и Grid/List в Preferences DataStore. Схема v1; изменения выполняются атомарными транзакциями. Неизвестная версия схемы не перезаписывается. При повреждении самого файла Preferences DataStore восстанавливаются пустые настройки.
- `data/LauncherCatalog.kt` получает приложения текущего профиля через `LauncherApps`, загружает подписи и иконки вне UI-потока и подписывается на изменения пакетов. Рабочие профили не поддерживаются.
- `ui/WorkspaceViewModel.kt` координирует чтение, изменения, обновление каталога и ошибки, предоставляя UI состояние через StateFlow.
- `ui/WorkspaceScreen.kt` отображает рабочие пространства, окно выбора приложений с поиском и состояния ошибок. `ui/HomeSettings.kt` открывает системные настройки HOME с запасными маршрутами в настройки приложений по умолчанию и общие настройки Android.

`HorizontalPager` переключает три пространства свайпами. Grid/List переключает адаптивную сетку и список. При первом запуске пространства пусты. Приложения добавляются флажками в окне «Добавить приложения». Кнопка «Убрать» снимает закрепление только с выбранного пространства; одно приложение может присутствовать на нескольких пространствах.

В хранилище записываются имена компонентов, а не иконки или подписи. Каталог обновляется при возврате на HOME и через `LauncherApps.Callback`. Удалённый пакет очищается из всех пространств; при перезапуске отсутствие пакета дополнительно проверяется через `getApplicationInfo`. Само отсутствие launcher activity не считается удалением пакета. Для временно недоступных компонентов остаётся плитка «Недоступно» с возможностью снять закрепление.

Для Android 11+ манифест объявляет адресную видимость приложений с intent `MAIN` / `LAUNCHER` через `<queries>`. Это позволяет находить приложения с запускаемым экраном без `QUERY_ALL_PACKAGES`; одна только регистрация HOME не заменяет такое объявление. См. [документацию Android о видимости пакетов](https://developer.android.com/training/package-visibility/declaring).

Ошибки чтения/записи настроек, загрузки каталога и запуска приложений отображаются пользователю. При ошибке чтения изменения отключаются до повторной попытки, а кнопка выбора другого лаунчера остаётся доступной. При ошибке записи интерфейс отражает последнее успешно сохранённое состояние.

## Проверка

Unit-тесты проверяют восстановление после пересоздания DataStore, конкурентное закрепление без потери изменений, независимость удаления закреплений и очистку всех activities удалённого пакета. Они не заменяют проверку поведения HOME и системных настроек на устройстве.

Gradle Wrapper и GitHub Actions собирают debug APK; CI выполняет unit-тесты перед сборкой. Подтверждённые результаты и версии инструментов перечислены в [BUILD](BUILD.md). Проверка установки и работы Workspace Manager на реальном устройстве остаётся открытой.

## Планируемые компоненты

- Дополнительные раскладки columns и master-stack и перемещение плиток касаниями.
- Android-виджеты через `AppWidgetHost`.
- Экран настроек оформления.
- Версионированные конфигурации TOML: импорт, экспорт, валидация, предпросмотр и откат.
- Позднее — импорт из GitHub и ZIP, каталог тем.

Эти компоненты пока не реализованы. Для MVP не предполагается обязательный удалённый сервер.

## Ограничения платформы

Обычный лаунчер не может произвольно перемещать, изменять размеры или встраивать окна любых сторонних приложений без привилегированных Android window API. Управляемые раскладки относятся к собственным плиткам, виджетам и другим компонентам HyprDroid.

Системные режимы split-screen/freeform могут исследоваться отдельно с учётом версии Android и производителя устройства. Их универсальная доступность не гарантируется и не является критерием MVP.

Пользователь может выбрать другой HOME-лаунчер через системные настройки. Кнопка «Другой лаунчер» предоставляет прямой переход к ним; остальные установленные лаунчеры не отключаются.

## Требования к будущему импорту конфигураций

Конфигурации являются данными: выполнение скриптов и произвольного кода запрещено. Импорт должен проверять версию схемы и содержимое, показывать предпросмотр и позволять откат к рабочей конфигурации. Для архивов необходимы ограничения размера и защита от небезопасных путей извлечения. Это требования к будущему импорту, а не существующая функция DataStore.

## Критерии MVP

- APK устанавливается на поддерживаемое устройство и доступен в выборе домашнего экрана.
- Пользователь видит и запускает доступные приложения, переключает независимые рабочие пространства свайпами.
- Пользователь импортирует валидный TOML-конфиг с темой и раскладкой, видит предпросмотр и может отменить применение.
- Некорректный импорт не лишает пользователя рабочего домашнего экрана.
- Пользователь может вернуться к другому лаунчеру через настройки Android.

MVP пока не завершён. Root-модули, собственная прошивка, управление окнами чужих приложений, маркетплейс с аккаунтами и выполнение сторонних скриптов не входят в его объём. Лицензия проекта пока не выбрана.
