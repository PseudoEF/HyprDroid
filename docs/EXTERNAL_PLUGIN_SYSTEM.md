# External Plugin System v0.5

## Результат аудита

`HyprPackageManager` использует тот же атомарный реестр и staging для локальных и сетевых пакетов. `HypPackageVerifier` проверяет SHA-256 и Ed25519 точных байтов ZIP до распаковки, затем проверяет манифест, пути, размеры, степень сжатия, CRC и наличие точки входа. Установленный реестр хранит манифест и каталог распакованных файлов. Он не хранит подписанную идентичность каждого распакованного файла.

`LuaPluginService` не экспортируется и работает под отдельным изолированным UID. `LuaPluginIpc` использует приватный Messenger и проверку UID, ограничивает DTO и проверяет дерево UI на стороне Core. `PluginApi` выдаёт фиксированные разрешения встроенным модулям. `TilePluginSession` разделяет состояние по тайлам, ограничивает события видимыми кнопками и игнорирует поздние ответы после остановки. `TileCommands` допускал и по-прежнему допускает только подписанный образец встроенного DroidFetch. Stateful Lua-замыкания создаются заново для каждого запуска, сохраняется строковое состояние Tile API.

`TrustedLuaRuntime` использует LuaJ без стандартных библиотек и без прямого Android API, reflection или shell. Лимиты инструкций и времени проверяются на шагах интерпретации. Жёсткой квоты памяти нет. Отвязка Binder после таймаута ограничивает ожидание Core, но не доказывает немедленную остановку worker, в частности при выделении памяти или зависании внутри операции VM. Android, ART, LuaJ и декодирование Bundle остаются в границе доверия. Подпись издателя удостоверяет происхождение байтов и не устраняет эти ограничения. Поэтому исполнение распакованных файлов не подключено. [Действующий Lua Runtime](LUA_RUNTIME.md) · [Tile API](TILE_PLUGIN_API.md)

## Сетевой каталог и установка

- `SignedPackageRepository` добавляет источник каталога и архивов, а `HyprPackageManager` использует существующие проверки, зависимости, атомарную публикацию и откат. Каталог хранится отдельно от реестра в приватном файле, заменяемом атомарно после проверки. Источник из APK и его ключ сохранены независимо.
- Конверт каталога содержит `keyId`, `payload` в Base64 и hex-подпись Ed25519. Подпись охватывает строку `HyprDroid catalog v1` с LF и точные байты payload. Внутри payload подписаны ID репозитория, ревизия, манифест каждого пакета, версия, SHA-256, подпись архива, канонический URL GitHub Releases и статус.
- APK задаёт ключ издателя отдельно от ключа встроенного пакета и минимально допустимую ревизию. Кэш фиксирует высшую принятую ревизию. Проверка отклоняет меньшую ревизию, изменение содержимого той же ревизии, понижение версии пакета и подмену записи с той же версией. Записи могут перейти в `revoked` и сохраняются в последующих ревизиях. Отозванную версию нельзя включить снова без повышения версии.
- Клиент принимает HTTPS с GitHub и одно перенаправление на выделенный CDN Release Assets. Читаются ограниченные объёмы, применяется таймаут подключения и чтения и бюджет загрузки, проверяемый между чтениями. URL пакета обязан точно соответствовать его ID и версии. Хеш и подпись архива проверяются независимо от адреса CDN.
- `hypr repo list` показывает состояние доверия и ревизию, `hypr repo update` явно обновляет каталог, а `hypr install` и `hypr update` используют принятый каталог. Полный ID имеет приоритет, короткое имя после последней точки принимается при однозначном совпадении. Без сети доступны встроенные и уже установленные пакеты, а сохранённый каталог используется для поиска. Сетевые архивы повторно загружаются при установке.
- В production-конфигурации ключ издателя ещё не утверждён. `hypr repo update` при этом возвращает явную ошибку и не делает сетевой запрос. Встроенный DroidFetch продолжает использовать свой подписанный образец.

Защита от отката действует, пока сохранён кэш. После очистки данных действует минимум в APK. Подписанного срока годности каталога пока нет, поэтому отказ от доставки свежей ревизии сам по себе не обнаруживается. Кэширование на случай отсутствия сети допускает устаревшую ревизию и задерживает получение отзывов.

## Предлагаемый контракт внешнего запуска

1. Выбрать VM с проверяемым лимитом памяти, например PUC Lua с аллокатором на состояние и ограниченным JNI-мостом. Оставить изолированный UID и проверить возможность гарантированной остановки worker под нагрузкой и после таймаута.
2. Передавать проверенные неизменяемые байты точки входа или ограниченный read-only дескриптор через типизированный Binder-контракт. Сохранить подписанную идентичность архива и файлов в существующем реестре. Перед каждым запуском сверять актуальные полномочия, версию и хеш точки входа.
3. Core выдаёт разрешения для конкретного модуля и проверяет каждую привилегированную операцию. Отзыв разрешения или удаление отключает события, завершает сессии и освобождает привязку. Акторы двух тайлов не разделяют состояние.
4. Проверить отказ при ошибке Binder, смерть процесса, злонамеренные аллокации, повторное связывание, два экземпляра и удаление модуля на Android. Лишь после этого согласовать включение маршрута `hypr tile add` для внешних пакетов.

## Публикация и Pixel 9

Черновик отдельного репозитория содержит `modules/hello-tile`, инструменты подготовки воспроизводимого ZIP и подписанного каталога, PR CI с правом чтения и спецификацию публикации. Выделенной публикации из PR нет. Артефакты подписываются на доверенной машине после ревью, а закрытый ключ хранится вне рабочего дерева. Реальные релизы и новый репозиторий требуют подтверждения владельца.

На Pixel 9 при текущей конфигурации проверьте `hypr repo list`, отказ `hypr repo update` до утверждения ключа, установку встроенного образца, `hypr tile add hyprdroid.droidfetch-sample`, Refresh и `demo install`. Проверьте inline prompt в узком тайле с IME. После утверждения ключа и публикации пробного каталога проверьте обновление, установку `hello-tile`, повторное открытие кэша в авиарежиме и отказ `hypr tile add hello-tile`. Последний отказ ожидается до отдельного разрешения внешнего запуска.

Для владельца остаются решения о создании публичного репозитория, ключе и минимальной ревизии APK, правилах ревью и пробной публикации, а также об архитектуре внешнего Runtime и критериях допуска.
