# Обновление APK и идентификация сборок

## Power Menu и TopBar v0.9

Текущий вариант оставляет TopBar только на Home: глобальное окно удалено после исследования API Android17. Даже старый Always visible не запускает док. Запись глобальных параметров остаётся неактивной; master-switch и настройки боковых панелей не сбрасываются. Usage Access больше не используется. Accessibility остаётся отдельным добровольным доступом только для Power Menu. Устанавливайте новый подписанный APK поверх прежнего без удаления данных; проверка CI настроена на переход с 10091.

[Подписанный APK 10091](https://github.com/PseudoEF/HyprDroid/actions/runs/44073953591/artifacts/14324048985) собран из `297f713`. [CI обновления](https://github.com/PseudoEF/HyprDroid/actions/runs/44073953591) проверил переход **v0.8.0 / 10083 → v0.9.0 / 10091** через `adb install -r`: UID, firstInstallTime и побайтовые хэши обоих DataStore совпали. Сертификат прежний; переустановка с удалением не требуется. Это проверка эмулятора Android 15, не физического телефона.

APK10091 относится к завершённому эксперименту и всё ещё содержит глобальный док. Его нельзя использовать для проверки Home-only поведения. [Исследование и ограничения текущего варианта](TOPBAR_POWER.md).

## Обновление v0.5.2 → v0.6

Постоянная подпись v0.5.2 сохранена; совместимый APK обновляется поверх без удаления приложения. Workspace остаётся в схеме v2. Shell DataStore мигрирует v1/v2 → v3, сохраняя закрепления, порядок, dock, Sidebar, фон и неизвестные поля. Существующая установка получает Classic; новая — Clean. Наличие старых файлов фиксируется до открытия хранилищ, замена установленного APK также учитывается через PackageManager. Режим сохраняется и больше не определяется по наличию иконок.

Clean скрывает представление иконок, а не данные. Вернуть их можно через «Рабочий стол и панели» → Classic. Настройки поддерживают предпросмотр/отмену; dock и модули Sidebar настраиваются независимо. Даунгрейд shell v3 → v2 не поддерживается, старое приложение не должно перезаписывать новую схему.

## Подпись и версии с v0.5.2

`applicationId` остаётся `dev.hyprdroid.launcher`. Расположение DataStore сохранено, автоматической очистки или переустановки нет. Обновление требует совместимой подписи и подходящего versionCode — см. [подпись](https://developer.android.com/studio/publish/app-signing) и [версии Android](https://developer.android.com/studio/publish/versioning).

При аудите обнаружено:

- До v0.5.2 versionCode задавался вручную (v0.5: `6`), поэтому разные коммиты могли иметь одинаковые версию и имя `app-debug.apk`.
- Свежие CI runners создавали собственный debug-keystore. [Аудит старых APK](https://github.com/PseudoEF/HyprDroid/actions/runs/43762239335) подтвердил один applicationId, но разные сертификаты v0.4.1 (`400b0fe2…575e500`) и v0.5 (`1439d8be…f6be59e`). Они не образуют совместимую цепочку обновления.
- Во время подготовки этого PR main оставался на `64d83e1`, а интерфейс v0.3–v0.5 — в отдельных PR. Пересборка main не добавляет изменения из не объединённых веток.
- Подмены APK предыдущим артефактом в старом workflow не обнаружено. Одинаковые имена файлов/артефактов затрудняли выбор; новая публикация проверяет содержимое самого APK.

## Установка поверх предыдущей версии

1. Выберите успешный **Android debug APK** для нужной ветки и коммита. Распространение запускается владельцем через **Run workflow** или после push в main; PR-проверки не публикуют APK со случайной подписью.
2. Скачайте artifact `HyprDroid-debug-<versionCode>-run<runId>-attempt<attempt>`. Он содержит конечный `HyprDroid-0.6.0-<versionCode>.apk`, JSON-метаданные и SHA-256. Базовый тестовый APK A не включён в обычный артефакт.
3. Сверьте коммит и versionCode с нужным запуском. Более поздний коммит не всегда означает больший номер опубликованной сборки; сравнивайте versionCode.
4. Откройте APK установщиком Android и подтвердите обновление. Не удаляйте приложение перед штатным обновлением.
5. В **меню верхней панели → О приложении** проверьте versionName, versionCode, полный коммит, run ID и SHA-256 сертификата. Это сведения установленного пакета, а не имя скачанного файла.

Установщик может запросить разрешение установки из выбранного источника; приложение не получает новых разрешений. Открытые рабочие пространства, закрепления, порядок, параметры, dock, Sidebar и URI фона сохраняются при совместимом обновлении.

### Важный переход со старых CI APK

Новый постоянный сертификат имеет SHA-256:

```text
0050f5056cbb38e43045e45cf952a01ba45c771646e54585b3ecfef6534ba7e0
```

Если установленный APK подписан прежним случайным CI-ключом, обновить его новым ключом поверх нельзя. Приватный ключ невозможно восстановить из APK. Для перехода на новую цепочку может потребоваться **однократное ручное удаление и переустановка**, при которых Android удаляет данные приложения. Экспорт/импорт пользовательских настроек пока не реализован; не рассчитывайте на сохранение DataStore после удаления. Решение остаётся за пользователем. HyprDroid и workflow не переустанавливают существующее приложение автоматически и не очищают данные.

Если сохранился исходный keystore старой установки, совместимые обновления возможны с ним. Нельзя просто заменить текущие Secrets этим ключом: это нарушит уже начатую новую цепочку; сначала требуется отдельное решение о подписи.

## Для разработчиков: adb

При совпадении applicationId/сертификата и большем versionCode (замените имя примера именем скачанного APK):

```sh
adb install -r ./HyprDroid-0.6.0-10007.apk
adb shell dumpsys package dev.hyprdroid.launcher
apksigner verify --print-certs ./HyprDroid-0.6.0-10007.apk
```

`apksigner` находится в Android SDK Build Tools. Не используйте downgrade-флаг `-d`, `pm clear` или удаление приложения как обычный шаг обновления.

| Наблюдение | Что проверить |
| --- | --- |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | Сертификат установленного пакета и нового APK. Повышение versionCode не исправляет несовместимую подпись. |
| `INSTALL_FAILED_VERSION_DOWNGRADE` | Установлен более высокий versionCode; скачайте более новую опубликованную сборку. |
| Появилась вторая иконка | applicationId другого APK отличается; это отдельное приложение. |
| Установка успешна, но интерфейс прежний | Сверьте коммит в About с веткой запуска; main не содержит не объединённые PR. Проверьте выбранный APK, а не только название версии. |

Для локальных сборок остаётся стандартный локальный debug-keystore. Значение versionCode по умолчанию — `8`, выше локального v0.5.2 (`7`); его можно задать `-PbuildVersionCode=<N>`. Сохраняйте один локальный keystore и увеличивайте N для своей цепочки. Локальный ключ обычно несовместим с подписью официального CI; такие APK не публикуются workflow как обновления CI.

## Как устроена публикация CI

- Проверки PR запускаются без постоянного ключа. Подписывающий job исполняется только для доверенного workflow_dispatch или push main, после unit-тестов и сборки.
- Приватный PKCS12 и пароль хранятся в GitHub Actions Secrets `HYPRDROID_KEYSTORE_BASE64` и `HYPRDROID_KEYSTORE_PASSWORD`. Временный файл создаётся с правами `0600` в RUNNER_TEMP и удаляется по завершении. В репозитории — только [публичный отпечаток](../config/debug-signing-cert.sha256); в артефакты и кэш ключ не загружается. При отсутствии/несовпадении ключа публикация прекращается, случайная подпись не подставляется.
- Общая concurrency-группа сериализует публикации. Счётчик использует неизменяемые теги `ci/debug/<N>`, начиная с `10000`. Каждый запуск резервирует пару следующих значений; конечный APK использует старшее. Первый номер может остаться резервом при тесте с фиксированной старой версией A. Пропуски допустимы. Повтор старого коммита с новым workflow получает новые номера; run_number, timestamp и run_id не используются как Android versionCode.
- **Не удаляйте/не перемещайте теги ci/debug/**: это долговременная история счётчика, независимая от истечения artifact. Main при резервировании не меняется. Перед резервированием проверяется предел `2100000000`; переполнение не приводит к сбросу номера.
- В APK встроен `assets/build-info.json` (applicationId, versionName/code, commit, run ID, канал). Перед upload проверяются подпись через apksigner, манифест через aapt и соответствие встроенных данных текущему запуску. SHA-256 вычисляется для конкретного файла. В staging-каталоге конечного артефакта нет APK из предыдущих запусков.
- APK B публикуется только после успешного теста A → B. Отчёт `HyprDroid-update-report-run…-attempt…` содержит метаданные обеих сборок, результат установки и хеши DataStore до/после обновления. Артефакты хранятся 14 дней.

Старые запуски до v0.5.2 остаются историческими: их APK не становятся совместимыми от повторного скачивания. Скачивайте артефакты новой цепочки и сверяйте About.

## Управление постоянным ключом

Ключ для PseudoEF/HyprDroid уже настроен. Не запускайте подготовку нового ключа для обычной сборки и не перезаписывайте Secrets при каждом запуске. От потери или замены ключа зависит совместимость всей цепочки.

Для нового форка/явно согласованной новой цепочки владелец может использовать `Prepare encrypted signing key`: передать публичный ключ шифрования и key_id из `gh api repos/OWNER/REPO/actions/secrets/public-key`. На runner генерируется кандидат, который шифруется GitHub sealed box **до** upload. Artifact содержит только зашифрованные API payload и публичный сертификат, не исходный keystore/пароль. Workflow сам не меняет Secrets.

После проверки владелец применяет зашифрованные payload через GitHub API:

```sh
gh api --method PUT repos/OWNER/REPO/actions/secrets/HYPRDROID_KEYSTORE_BASE64 --input keystore-secret.json
gh api --method PUT repos/OWNER/REPO/actions/secrets/HYPRDROID_KEYSTORE_PASSWORD --input password-secret.json
```

Публичный `certificate.sha256` затем фиксируется в config/debug-signing-cert.sha256. Это операция создания/смены цепочки подписи, а не обновление устройства; возможность потери данных при переходе требует отдельного предупреждения. Не публикуйте исходные ключи и пароли в Git, логах, issue или обычных артефактах.

## Границы проверки

В CI v0.6 базовый APK A пересобирается из закреплённого исходного v0.5.2 (`b811483`, код `10005`) с прежним постоянным ключом. Это независимая версия кода с shell v2, а не переименованный v0.6; истечение старого artifact не мешает тесту. APK B — текущий v0.6 с новым кодом. Свежий эмулятор сохраняет состояние в A, выполняет `adb install -r B` без удаления, сравнивает байты DataStore **до первого чтения миграцией**, UID/firstInstallTime и модели после миграции. Shell получает новые поля v3, прежние данные и Classic сохраняются, About проверяет новую версию/код/коммит/сертификат. Сохранение реального URI-разрешения на выбранный файл и установщик конкретного телефона требуют проверки на устройстве; фикстура проверяет хранение URI как данных. Результаты — в [BUILD](BUILD.md).

## Эксперимент v0.6.2

Overlay Sidebar выключена после обновления с v0.6.1 и на новых установках. Для проверки откройте меню верхнего бара → «Настройки панелей», выдайте разрешение в Android, вернитесь в HyprDroid и включите панель. Предоставление разрешения само по себе не включает функцию. Появится уведомление foreground-службы с действием «Отключить»; выключение доступно также в настройках HyprDroid, отзыв разрешения — в Android.

В стороннем приложении проведите влево из небольшого маркера справа или коснитесь его. Если Back имеет приоритет, увеличьте отступ зоны. Полная замена системного Back не гарантируется. Основная оболочка и переключение HOME доступны без overlay-разрешения. После перезагрузки/остановки службы откройте HyprDroid для возобновления ранее включённого режима.

Данные workspace и Sidebar не очищаются; новые параметры добавлены в существующий shell DataStore v3 с выключенным значением по умолчанию. CI проверяет обновление с исходного v0.6.1 (10015), используя прежний сертификат. На физическом устройстве проверка учитывается отдельно.

Foreground-служба создаёт уведомление, но Android 13+ может скрывать его из обычной шторки, если уведомления приложения не разрешены. Дополнительное runtime-разрешение на уведомления не запрашивается. Отключение доступно также прямо в overlay-панели и в системном списке активных приложений.

## Universal Panels поверх первого v0.6.2

Новая сборка сохраняет versionName `0.6.2`, но получает больший versionCode и новый коммит в About. Для установки поверх APK 10023 используйте опубликованный подписанный артефакт нового запуска; `adb install -r` и обычный установщик сохраняют данные при совместимой подписи.

Прежнее включение overlay не сбрасывается. Правая сторона наследует высоту, положение, отступ и включённые модули: при включённом overlay получает «Везде», иначе — «Только Home». Левая появляется в Home с часами, датой и батареей. Никаких ярлыков или рабочих пространств миграция не удаляет.

Меню → «Настройки панелей»: выберите сторону, режим, параметры маркера/сенсорной зоны и порядок модулей, затем «Сохранить панель». Back отменяет несохранённый черновик. Для работы вне Home сохраните «Поверх приложений» или «Везде» хотя бы у одной стороны, выдайте разрешение Android и включите overlay. Это общий выключатель службы; доступность сторон определяется независимо. Если все стороны только Home, служба останавливается, а Home-панели остаются доступны.

Скрытый маркер оставляет зону активной. Если жесты приложения или Android Back конфликтуют, уменьшите ширину сенсорной зоны и увеличьте отступ. Панели доступны и через кнопки Home; глобальную панель можно открыть касанием зоны. На защищённых системных экранах Android может скрывать overlay независимо от выбранного режима.

## v0.7 — стандартные Android-виджеты

В меню Home откройте «Настройки панелей», выберите сторону, сохраните изменения и нажмите «Добавить Android-виджет». Выберите установленного поставщика. Подтвердите привязку в системном диалоге и настройку поставщика, если Android их запросит. Добавление сохраняется после успешной конфигурации. Незавершённая операция показывается в настройках: её можно продолжить или отменить; повторно выделять ID не требуется.

Каждый экземпляр находится в общем списке модулей. «Выше / Ниже» меняют порядок; «Убрать» и размеры применяются после «Сохранить панель». Back отменяет черновик удаления/размера. Нересайзируемые поставщиком направления недоступны; фактический размер ограничен доступной панелью и правилами поставщика. Виджет можно добавить несколько раз.

Для Global Overlay сохраняются прежние режимы панелей и добровольное SYSTEM_ALERT_WINDOW. Интерактивность зависит от поставщика и Android: например, запуск Activity или ввод могут быть ограничены. Используйте Home для привязки/конфигурации и действий, которые не поддерживаются в overlay. Настройки и привязки не удаляются при отключении overlay. Без root, AccessibilityService, Shizuku или ADB для конечного пользователя.

Обновление с v0.6.2 сохраняет workspace, ярлыки, размеры маркеров, настройки панелей, фон и dock. Документ панелей получает схему 2 при сохранении новых данных; версия 1 читается без сброса. После сохранения схемы 2 старый APK v0.6.2 не сможет читать настройки панелей: принудительный даунгрейд не поддерживается. Удаление приложения Android также удаляет его host-привязки; для обычного обновления устанавливайте совместимый подписанный APK поверх старого.

Если поставщик удалён/отключён или привязка недоступна, останется заглушка с сохранённым местом и размером. Можно повторить чтение, удалить запись или добавить виджет заново через системное согласие. Не все ограничения конкретных сторонних виджетов воспроизводимы на эмуляторе; проверка телефона учитывается отдельно.

## v0.7.1 — редактор панелей

В «Настройках панелей» выберите сторону и категорию. В «Содержимом» нажмите строку модуля: откроются его действия и, для Android-виджета, размеры. Настройки других элементов свернуты. В «Внешнем виде» задаётся независимая ширина всей панели. «Предпросмотр» показывает черновик без записи; вернитесь и нажмите «Сохранить панель». Back/«Назад» отменяют несохранённые изменения. Добавление нового Android-виджета требует сначала сохранить черновик и по-прежнему проходит системное согласие Android.

В открытой панели нажмите «Редактировать панель» либо удерживайте заголовок виджета. В обычном содержимом виджета удержание принадлежит самому виджету. В редакторе выберите строку, измените размер ручкой/ползунками, порядок кнопками «Выше/Ниже» или удалите модуль. Просмотр защищён от случайных действий виджета. Нажмите «Сохранить» или «Отмена». Эти действия доступны и в Global Overlay; системный Back в overlay закрывает окно и отменяет черновик. Включение overlay и ограничения Android остаются прежними.

Старые панели читаются без сброса с шириной 80%. После сохранения используется схема панелей v3; downgrade к v0.7 не поддерживается. Обновляйте APK с прежним ключом поверх установленного приложения, без удаления данных. Постоянные widget ID и остальные хранилища не меняются.

В «Рабочий стол и панели» настройте Drawer отдельно для Topbar/Dock: «Авто» скрывает кнопки в Clean и показывает в Classic; «Вкл/Выкл» переопределяют это. Кнопка Sidebar отключается отдельно. Свайп вверх, меню «Все приложения», меню Sidebar и настройки остаются доступны. Предпросмотр применяется после «Сохранить»; Back или свайп вправо по заголовку отменяют изменения. Меню оболочки также закрывается свайпом вправо по своему заголовку; кнопки/прокрутка содержимого и системные края сохраняют свои жесты.

Для GIF выберите «Выбрать изображение…» и локальный GIF в системном picker. Приложение сохранит приватную копию, поэтому удаление исходного файла не уберёт уже выбранный фон. Разрешения на весь медиакаталог не нужны. Допустимы файлы до 24 МиБ, 8 Мп и 8192 px по стороне; большой файл уменьшается при декодировании до 1024 px (512 при малом объёме памяти). Ошибка импорта сохраняет предыдущие обои.

В настройках доступны заполнение с обрезкой, вписывание и растягивание, а также отключение анимации. Анимация останавливается вне видимого Home, под меню/панелями, при выключенном экране и в Battery Saver; при возвращении может начинаться с первого кадра. Статичные изображения, системные/живые системные обои и прежние настройки сохраняются. GIF работает только внутри рабочего стола HyprDroid и может расходовать больше батареи, чем статичный фон. Проверяйте подходящий размер файла на своём телефоне.
