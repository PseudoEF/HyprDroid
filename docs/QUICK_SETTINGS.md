# Quick Settings v0.8

Плитки — встроенные модули существующих панелей (`QS_*`). Прежний Control Center стал единой шторкой Quick Settings; отдельного popup из шестерёнки больше нет. Общая реализация плиток/ползунков обслуживает шторку Home и обе боковые панели в Home/Global Overlay. Это не замена системному Quick Settings и не глобальный перехват жестов.

## Настройка

Свайп вниз по свободному Home открывает шторку: часы, дата, батарея, отдельные ползунки и сетка плиток в две колонки. Закрытие — свайп вверх по заголовку (по содержимому — у границы прокрутки), Back, X или нажатие на затемнение снаружи. Шторка имеет высоту по содержимому с пределом 85% доступного экрана и ширину до 520 dp; заголовок остаётся доступным при прокрутке. Меню → **Quick Settings** даёт альтернативу жесту. Шестерёнка верхнего бара открывает настройки HyprDroid, шестерёнка шторки — её редактор.

Меню → **Quick Settings · редактор**: выберите «Верх», «Слева» или «Справа». Каждая плитка имеет одну строку с checkbox и доступными кнопками «Выше/Ниже», без раскрывающихся подменю. Предпросмотр и сведения о разрешениях свёрнуты по умолчанию. «Сохранить размещение» применяет выбранное размещение; выход или смена вкладки с черновиком требует подтверждения отмены. Удаление всех верхних плиток оставляет часы/статус и доступ к редактору. В шторке яркость/громкость вынесены в отдельную область; порядок сохранён внутри группы ползунков и внутри сетки. Боковые модули сохраняют общий порядок панели.

Боковые плитки также доступны через прежний редактор модулей панелей. Их режим Home/поверх приложений/везде, ширина и жесты задаются обычными настройками панелей. Одна плитка может присутствовать в нескольких размещениях; системное состояние у неё общее. Остальные модули, Android-виджеты и неизвестные записи сохраняются.

## Действия и ограничения Android

| Плитка | Короткое нажатие | Долгое нажатие / состояние |
| --- | --- | --- |
| Wi-Fi | Публичная системная Settings Panel Wi-Fi | Полные настройки Wi-Fi; показывается включение адаптера, без SSID/сканирования |
| Bluetooth | Системные настройки Bluetooth | Те же настройки; Android 12+ требует добровольный BLUETOOTH_CONNECT для чтения состояния |
| Фонарик | CameraManager.setTorchMode; перед первым использованием отдельный экран и системный запрос CAMERA | Сведения о HyprDroid/разрешения: публичного универсального экрана настроек фонарика нет |
| Не беспокоить | Системная конфигурация Zen/DND | Тот же системный экран; показывается текущий interruption filter |
| Яркость | Нажатие заголовка — настройки дисплея; отдельный ползунок пишет значение при WRITE_SETTINGS и ручном режиме | Настройки дисплея; авто не отключается скрытно, процент помечен оценкой |
| Громкость | Нажатие заголовка — системный UI громкости; отдельный ползунок регулирует медиа | Настройки звука; рингтон/DND не переключаются |
| Автоповорот | Переключение ACCELEROMETER_ROTATION при WRITE_SETTINGS; иначе системные настройки поворота/дисплея | Те же настройки |
| Настройки | Системные настройки Android | Те же настройки |

Если Activity отсутствует или Android отклоняет действие, используется общий экран настроек и/или понятное сообщение. После перехода в другое Activity раскрытая панель закрывается, включая Global Overlay. Разрешения могут быть отозваны в любой момент: UI перечитывает их, а операции обрабатывают отказ без выдачи его за успешное переключение.

Сторонний targetSdk 35 не переключает Wi-Fi напрямую; Bluetooth enable/disable также ограничены. Для DND не запрашивается Notification Policy Access: на Android 15 setInterruptionFilter уже не является универсальным глобальным переключателем для обычного приложения. Фонарик может быть занят камерой или недоступен из overlay из-за ограничений Android/OEM. При уходе процесса Android может выключить принадлежащую ему вспышку; отдельного фонового сервиса камеры нет.

## Разрешения

Ничего не запрашивается при первом запуске лаунчера:

- `ACCESS_WIFI_STATE`: обычное разрешение только на состояние адаптера; нет доступа к сетям/местоположению и изменения Wi-Fi.
- `CAMERA`: опасное, только после нажатия фонарика и поясняющего экрана. Камера не открывается, запись фото/видео отсутствует. Отказ сохраняет остальные функции.
- `BLUETOOTH_CONNECT`: Android 12+, добровольно через редактор для статуса; поиска и подключения устройств нет. До Android 12 — обычное BLUETOOTH, ограниченное maxSdkVersion 30. Без разрешения статус честно помечен недоступным, а системный интерфейс работает.
- `WRITE_SETTINGS`: специальный доступ через отдельную кнопку редактора и системный экран; только яркость/поворот. Без него используются настройки Android.

Камера, автофокус и вспышка объявлены необязательными аппаратными возможностями. Для плиток не используются root, AccessibilityService, скрытые API или Bluetooth scan, Change Wi-Fi State, новых foreground services или доступа к содержимому уведомлений.

## Архитектура и хранение

`QuickTile` задаёт стабильные ID/названия. Те же ID зарегистрированы в `PanelModule`, порядок боковых плиток хранится прежним `PanelsCodec` v3. Для верхнего блока добавлен JSON v1 `quick_settings_configuration` внутри существующего shell DataStore. Старые записи и схема shell v3 не сбрасываются, неизвестная конфигурация не перезаписывается молча. Начальный верхний блок содержит все восемь плиток; боковые панели автоматически не меняются.

`QuickSettingsController` использует application context, общие StateFlow и счётчик видимых потребителей. При STARTED подключаются TorchCallback, системные broadcasts и ContentObserver; оставшиеся значения, включая медиагромкость и разрешения, перечитываются раз в две секунды только пока видна хотя бы одна поверхность плиток. При STOP/dispose наблюдатели и polling отключаются. Системное состояние не записывается в DataStore и не подменяется оптимистичным «вкл» до ответа Android. `TilePermissionActivity` предоставляет явный пользовательский вход и из Home, и из overlay без ActivityResultRegistry в сервисе.

## Почему яркость могла показывать 7% вместо 56%

Старая реализация вычисляла `SCREEN_BRIGHTNESS * 100 / 255`: это доля целочисленного значения настройки, а не процент ползунка Android. Значения 18–20 давали 7%. В [AOSP Settings](https://android.googlesource.com/platform/packages/apps/Settings/+/refs/heads/main/src/com/android/settings/display/BrightnessLevelPreference.kt) процент вычисляется нелинейно по текущей яркости и границам дисплея. [HLG-преобразование AOSP](https://android.googlesource.com/platform/frameworks/base/+/main/core/java/com/android/internal/display/BrightnessUtils.java) поясняет различие линейного и воспринимаемого уровня. Эти внутренние классы/события не вызываются из HyprDroid.

Теперь локальная математическая шкала `BrightnessScale` преобразует документированный диапазон 1–255 в воспринимаемый уровень HLG и обратно при ручной записи. UI показывает **«≈…% · оценка HLG»**, а не точный процент Android. Например, для 18 получается около 45%, а не 7%; это **не доказательство совпадения с 56%** конкретного телефона. Границы, калибровка, текущий display level и OEM-поведение могут отличаться от принятого диапазона. Без данных устройства нельзя приписать наблюдение одной конкретной причине.

При адаптивной яркости сохранённая настройка может отличаться от текущего результата регулирования Android. Поэтому показано **«Авто · уровень задаёт Android»**, процент и ручная запись отключены, остаётся системный экран. Ошибка чтения не заменяется выдуманными 50%/0%; неизвестный режим тоже не считается ручным. Для проверки на телефоне нужно сравнить ручной и автоматический режимы, исходное значение Settings.System и системный ползунок; совпадение процентов на всех устройствах не обещается.

## Проверка на устройстве

CI не заменяет проверку физического телефона. Требуется проверить фонарик при занятой камере/отказе/отзыве CAMERA, возврат из системных экранов, Bluetooth со статусом без разрешения и после grant, ручную/автоматическую яркость, громкость на разных аудиоустройствах, автоповорот после отзыва WRITE_SETTINGS, Home/overlay/экран блокировки и возврат Back. При обновлении APK должны сохраниться виджеты, GIF, панели и рабочие пространства.

### Power Menu в v0.9

Кнопка питания в заголовке шторки открывает [Power Menu](TOPBAR_POWER.md#power-menu). Отдельная необязательная AccessibilityService используется только для системного Power Dialog, не для чтения состояний или управления плитками. В Home остаётся прежний свайп вниз; боковые QS-модули работают по прежним правилам. Эксперимент глобального TopBar завершён, меню дока над чужими приложениями удалено.
