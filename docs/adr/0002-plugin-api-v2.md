# ADR 0002. Plugin API v2

## Решение

Сохранить отдельный режим v1 для опубликованного Hello Tile и встроенного DroidFetch. API пакета берётся из подписанного манифеста и проверяется Core до IPC. Для v2 Core отдельно проверяет точную привязку издателя и артефакта, совместимость API и возможности. Признание манифеста формата v2 не даёт право запуска.

V2 использует типизированное дерево с проверкой на стороне Core до Compose. Событие содержит тип, ID, значение и ревизию отображённого дерева. Core проверяет принадлежность экземпляру и валидность payload. При смене дерева старые callbacks теряют допуск. Для программных событий используются отдельные пространства имён, без возможности имитации пользовательского ввода из Lua.

Запрос worker должен содержать один проверенный снимок состояния, одно событие и только разрешённые системные поля. Ответ содержит декларативный UI, предлагаемое состояние и декларации таймеров. Изолированный процесс не получает Android Context, Binder системных служб или пути. Используется существующая read-only SharedMemory, один запрос и ответ на worker и прежние лимиты VM. Версия wire-протокола отличается от подписанной версии Plugin API и проверяется отдельно.

Одна запись Core на экземпляр содержит версию схемы, ревизию и ограниченный словарь скалярных значений. Для v1 остаётся текущий слот строки. V2 использует отдельную схему. Любая будущая миграция требует отдельного доверенного преобразования с сохранением старой записи до успешной фиксации. Удаление тайла удаляет его записи, удаление пакета сохраняет их до повторной совместимой установки или явной очистки.

Таймеры принадлежат Core. На активный экземпляр допускаются два таймера с интервалом от секунды. Невидимый тайл и Activity ниже STARTED не получают тики. При возвращении дедлайн назначается заново. Пропущенные тики пропускаются. Resume относится к переходу видимого тайла из неактивного в активный в рамках одной Activity. Для каждого перехода Core выпускает одно событие. Пересоздание worker само по себе не считается переходом.

Системные данные представляются ограниченными DTO. Поля батареи требуют `system.battery`, время требует `system.time`, состояние требует `state.local`. Отсутствующие данные представлены отсутствующим полем. Версия 1 сохраняет прежний набор разрешений.
