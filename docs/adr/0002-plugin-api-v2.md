# ADR 0002. Plugin API v2

## Статус реализации

Подключён тестовый путь v2 для двух зафиксированных артефактов. Новый запрос `createSessionV2` использует wire version 1 независимо от `apiVersion: 2`. AIDL передаёт ID одноразовой сессии, версию, маску capabilities, тип события и два read-only SharedMemory. Формат контекста использует ограниченные UTF-8 токены с длиной, типизированные скаляры состояния и один снимок системных данных. Результат содержит ограниченный блок дерева, предложение состояния и до двух таймеров. Ошибки и отмена используют существующий Binder и подтверждение смерти worker. Binder API v1 сохраняется без изменения формата.

## Lua-контракт

- `ui.render(tree)` и `hypr.ui.render(tree)` эквивалентны. Строковые поля, типы узлов и ID проверяются Core. Для Icon узел использует поле `glyph` из закрытого набора.
- `ui.on(kind, id, function(event) ... end)` принимает `onClick`, `onChange`, `onSubmit`, `onTimer`, `onResume`. Resume использует пустой ID. Switch передаёт boolean, TextInput передаёт строку. Начальный chunk выполняется при каждом запросе и регистрирует обработчики заново.
- `state.get(key, default)` принимает значение по умолчанию, `state.set(key, value)` требует `state.local`. В ответе VM передаёт полный ограниченный снимок. Core проверяет его и выполняет compare-and-set в слоте схемы 2.
- `system.get("device.time")` возвращает таблицу с `date`, `time24`, `time12` в часовом поясе устройства. `battery.level` — целый процент, `battery.charging` — boolean. Снимок формируется в Core на одну операцию. Известное поле без разрешения или данных возвращает `nil`. Неизвестное имя завершает операцию ошибкой.
- `timer.every(id, milliseconds)` декларирует таймер в текущем результате. Разрешены два уникальных таймера с интервалом от одной секунды. Таймеры активны только на выбранной странице и при Activity в STARTED. Возобновление начинается с нового снимка, пропущенные тики не воспроизводятся.

Core валидирует дерево, состояние и таймеры до записи. Успешная транзакция состояния служит точкой фиксации. При отзыве до этой точки операция отменяется. Если Activity закрылась после фиксации, результат восстанавливается из состояния при следующем открытии. UI и таймеры не публикуются для скрытого или отозванного экземпляра.

## Установка тестовых пакетов и Pixel 9

1. Установить подписанный тестовый APK поверх 10179. Обычные сборки содержат прежний допуск v1.
2. Выполнить `hypr repo update`, `hypr install hello-tile` и `hypr tile add hello-tile`. Затем выполнить `hypr install clock-tile`, `hypr install battery-tile`, `hypr tile add clock-tile`, `hypr tile add battery-tile`.
3. У Clock проверить секунды и формат 12/24. У Battery проверить реальный процент, зарядку и Refresh. Сменить приложение и рабочее пространство, изменить размеры и перезапустить HyprDroid. Проверить сохранение формата и независимость состояния Hello Tile.
4. Удалить Clock командой `hypr remove clock-tile`. Убедиться, что тайл переходит в безопасное состояние и тики прекращаются. Повторно установить пакет, чтобы восстановить сохранённое состояние. Удаление самого тайла очищает слот.
5. Проверить HOME, DroidFetch, историю терминала и `demo install`.

Оба архива включены только в тестовый APK с явным флагом `v2FixtureLua`. Пакеты устанавливает штатный Package Manager с Ed25519 и SHA-256. Доверенная запись является частью подписанного APK. Перед запуском Core заново сверяет подписанный архив, точные байты скрипта, манифест, версию и разрешения. Ключ фикстур отделён от официального репозитория, приватная часть не сохраняется. Публичный каталог Packages не меняется.

## Решение

Сохранить отдельный режим v1 для опубликованного Hello Tile и встроенного DroidFetch. API пакета берётся из подписанного манифеста и проверяется Core до IPC. Для v2 Core отдельно проверяет точную привязку издателя и артефакта, совместимость API и возможности. Признание манифеста формата v2 не даёт право запуска.

V2 использует типизированное дерево с проверкой на стороне Core до Compose. Событие содержит тип, ID, значение и ревизию отображённого дерева. Core проверяет принадлежность экземпляру и валидность payload. При смене дерева старые callbacks теряют допуск. Для программных событий используются отдельные пространства имён, без возможности имитации пользовательского ввода из Lua.

Запрос worker должен содержать один проверенный снимок состояния, одно событие и только разрешённые системные поля. Ответ содержит декларативный UI, предлагаемое состояние и декларации таймеров. Изолированный процесс не получает Android Context, Binder системных служб или пути. Используется существующая read-only SharedMemory, один запрос и ответ на worker и прежние лимиты VM. Версия wire-протокола отличается от подписанной версии Plugin API и проверяется отдельно.

Одна запись Core на экземпляр содержит версию схемы, ревизию и ограниченный словарь скалярных значений. Для v1 остаётся текущий слот строки. V2 использует отдельную схему. Любая будущая миграция требует отдельного доверенного преобразования с сохранением старой записи до успешной фиксации. Удаление тайла удаляет его записи, удаление пакета сохраняет их до повторной совместимой установки или явной очистки.

Таймеры принадлежат Core. На активный экземпляр допускаются два таймера с интервалом от секунды. Невидимый тайл и Activity ниже STARTED не получают тики. При возвращении дедлайн назначается заново. Пропущенные тики пропускаются. Resume относится к переходу видимого тайла из неактивного в активный в рамках одной Activity. Для каждого перехода Core выпускает одно событие. Пересоздание worker само по себе не считается переходом.

Системные данные представляются ограниченными DTO. Поля батареи требуют `system.battery`, время требует `system.time`, состояние требует `state.local`. Отсутствующие данные представлены отсутствующим полем. Версия 1 сохраняет прежний набор разрешений.
