# ADR-0001 — Workspace Engine: внутренний движок размещения

## Статус

Принято. Этапы 1–4 реализованы как архитектурный фундамент (HyprDroid v0.9); исполнение внутренних модулей и подключение движка к UI — последующие шаги.

## Контекст

Home-лаунчер HyprDroid хранит собственные компоненты через типизированные workspace records (DataStore `workspaces`, схема v2) и overlay-панели (DataStore `shell`, схема v3). Текущая модель покрывает элементы, порядок и параметры, но не содержит вычисляемого дерева раскладки: позиция компонентов определяется данными редактора, а не чистой функцией. Для будущих internal модулей (`.hmod`) и тайлинга окон потребовался бы устойчивый контракт, версионируемое хранилище и инварианты без потери существующих данных.

## Решение

- Отдельный пакет `dev.hyprdroid.launcher.workspaceengine`: чистый Kotlin, без Android и Compose, без новых зависимостей.
- Отдельный DataStore (`workspace_engine`) со схемой движка; прежние `workspaces`, `shell`, панелей и фоновые ключи не изменяются.
- `WorkspaceTree(root: LayoutNode?, windows: Map<WindowId, WorkspaceWindow>, focusedWindowId: WindowId?)`.
- `SplitNode(id: SplitId, orientation: Orientation, ratio: Float в диапазоне 0.05..0.95, first: LayoutNode, second: LayoutNode)`; без `List`, ровно два потомка. `LeafNode(windowId: WindowId)`.
- Инварианты: набор листьев точно соответствует набору окон; `WindowId`/`SplitId` уникальны в пределах дерева; операции возвращают явный результат или типизированную ошибку и не оставляют повреждённого состояния.
- Координаты layout — целочисленные px; ratio — нормализованный Float; минимумы задаются в dp на границе UI, внутренний calculator получает готовые px-минимумы; отрицательных размеров нет, при нехватке — информация о нарушении.
- Layout — чистая функция; поворот экрана меняет только результат layout, дерево не меняется.
- Сериализация — версионированный формат v1; начальное состояние всех рабочих пространств — пустые деревья; неизвестная версия схемы и повреждённый JSON/дерево — `IOException`; миграция legacy не выполняется.
- `ModuleManifest(id, name, version, entrypoint, permissions)` — только контракт будущего `.hmod`; без WebView, ZIP, JavaScript и исполнения.

## Последствия

- Движок готов к подключению тайлинга, `.hmod` и редактора без изменений существующих настроек.
- Хранилище движка — отдельный DataStore, поэтому текущие пользователи получают пустое начальное состояние без миграции.
- Окна не реализованы и не запускаются: Engine покрывает модель и расчёт, исполнение модулей — отдельная фаза.
- Ограничения MVP: layout не учитывает системные инsets/окна навигации на границе UI; минимальные размеры проверяются на стороне расчёта, реальная клиппусясть — при интеграции с Compose.
