# Tile Plugin API v1

Core хранит раскладку и назначение модуля в существующем `WorkspaceEngineStore`. Каждый `WindowId` получает собственное состояние от `ModuleHost`. Активный модуль передаёт только описание своего содержимого. Размер, фокус, добавление, удаление и панель управления принадлежат Core. Lua не получает идентификаторы других тайлов и не вызывает операции тайлинга.

## Установка и запуск

Команды доступны в тайле «Команды» внутри открытого пространства тайлинга.

```text
hypr install hyprdroid.droidfetch-sample
hypr tile add hyprdroid.droidfetch-sample
hypr tile list
hypr tile remove <tile-id>
```

`hypr tile add` разрешён только для точного образца DroidFetch v1.0.0 из каталога APK. Package Manager проверяет Ed25519 и SHA-256 при установке. При добавлении тайла и при каждом запуске Core сверяет установленный манифест с закреплённой записью издателя, проверяет разрешения на устройство и батарею и сверяет SHA-256 установленной точки входа с известным образцом. Разрешение `ui.tile` закреплено самим Core за встроенным адаптером.

Скрипт внутри установленного `.hyp` остаётся данными. Он предшествует Tile Plugin API. Реальную декларацию выполняет [встроенный droidfetch-tile.lua](../app/src/main/assets/trusted-lua/droidfetch-tile.lua). Произвольные установленные пакеты не имеют маршрута к выполнению. Тот же адаптер можно выбрать в существующем Module Picker, где без установки отображается ошибка доступа.

Терминал запрашивает добавление и удаление через существующий Core. Добавление учитывает ограничения раскладки и возвращает ID созданного тайла. Список и удаление ограничены Lua-тайлами текущего пространства. Смена модуля в уже созданном тайле выполняется существующим меню.

## Lua API и протокол

```lua
hypr.ui.on("refresh", function()
    local device = hypr.system.getDeviceInfo()
    hypr.ui.render({ type = "text", value = device.model })
end)

hypr.ui.render({
    type = "column",
    children = {
        { type = "text", value = "Hello, HyprDroid!" },
        { type = "button", id = "refresh", text = "Refresh" },
        { type = "progress", value = 0.65 }
    }
})
```

В готовом модуле Refresh повторно строит весь интерфейс вместе с кнопкой. Описание принимает `text`, `button`, `column`, `row`, `progress`, `spacer`, `card` и корневой `scrollableColumn`. Для контейнера `children` — плотный массив, для `progress` `value` от 0 до 1, для `spacer` `size` целое число от 0 до 32 dp. Узлы, свойства и ID проходят проверку в worker. Core независимо разбирает ограниченный список строк из Binder и создаёт типизированное дерево Kotlin. Через Binder не проходят Lua-функции, произвольные Views или Compose-код.

Каждый запуск и клик используют существующий одноразовый `LuaPluginService` с `isolatedProcess=true`, отдельным UID и проверками UID отправителя. Lua-замыкания регистрируются заново из встроенного исходника, после чего вызывается только обработчик адресованной кнопки. Снимок устройства и батареи обновляется перед запуском. Состояние между вызовами хранится как строка длиной до 512 кодовых единиц через `hypr.ui.getState()` и `hypr.ui.setState(text)`. Состояние отделено для каждого тайла и очищается при его остановке. После пересоздания Activity Core восстанавливает назначение тайла и начинает с нового безопасного снимка.

Core принимает только ID кнопок из последнего дерева этого тайла. Пока выполняется запрос, следующие события пропускаются. Между запросами одного тайла выдерживается минимум 350 мс. При удалении, смене модуля или уходе из композиции сессия больше не применяет ответы, а отмена coroutine снимает Binder-привязку. Ошибка, отказ, таймаут и смерть процесса отображаются внутри тайла, с возможностью повторить запрос.

## Пределы

- До 48 узлов, 6 уровней, 256 кодовых единиц на текст и 4096 на дерево. ID кнопок уникальны, до 32 ASCII-символов. Одно обновление публикует последнее успешно сформированное дерево.
- Используются действующие бюджеты Lua для инструкций, времени, глубины стека и числа вызовов API. Ожидание Binder ограничено пятью секундами после начала привязки. Жёсткой квоты Lua-кучи нет.
- Изолированный UID и отсутствие системных библиотек Lua снижают риск. Эта версия рассчитана на встроенный доверенный скрипт. Граница зависит от Android, Binder, ART и LuaJ. [Lua Runtime](LUA_RUNTIME.md)

## Проверка на Android

1. Откройте тайлинг, назначьте одному тайлу «Команды» и выполните `hypr install hyprdroid.droidfetch-sample`.
2. Выполните `hypr tile add hyprdroid.droidfetch-sample`. Если рабочая область мала для второго тайла, назначьте «DroidFetch · Lua» на имеющийся тайл через его меню.
3. Сверьте модель, Android и заряд с системными настройками. Нажмите Refresh после изменения заряда. При недоступном значении ожидается сообщение и отсутствие шкалы.
4. Измените размер, поверните экран и проверьте повторный запуск тайла с актуальными данными. Создайте вторую копию и проверьте, что Refresh обновляет только выбранный тайл.
5. Выполните `hypr tile list` и удалите одну копию через `hypr tile remove <tile-id>`. После удаления пакета следующий Refresh в оставшемся тайле должен показать ошибку установки. Проверьте отказ для другого ID пакета.
6. При подключённом устройстве запустите `./gradlew :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=dev.hyprdroid.launcher.plugins.LuaPluginServiceTest` для проверки Binder.
